# AI / System Jargon Leak Ledger — Seed

## Core diagnosis

Terms that are useful in editing ledgers have leaked into manuscript prose. This makes the writing sound AI/system-like even when the underlying claim is correct.

| Phrase | Why it is risky | Prefer |
|---|---|---|
| empirical object | abstract and system-like | coefficient, series, estimate, measure, benchmark, specification |
| object of evaluation | bureaucratic | coefficient being replicated, relation being tested |
| replication target | acceptable sparingly, but too ledger-like if repeated | published estimate, reported coefficient, Shaikh’s benchmark |
| interpretive move | too meta | I interpret; this estimate can be read as; I treat this coefficient as |
| candidate transformation elasticity | dense if introduced too early | coefficient interpreted as an elasticity linking capital to capacity |
| system-admissibility gates | protocol language | VECM rank and stability checks; system-level tests |
| retained criteria | abstract | the tests used here; the retained VECM checks |
| bounded implications | AI-ish compression | limited implication; narrower conclusion; what the evidence supports |
| pressure points | generic AI planning language | specification choices; data choices; model checks |
| empirical architecture | system memo language | empirical design; sequence of tests |

## Rule

In manuscript prose, name the empirical thing directly. Use system vocabulary only in internal ledgers.
