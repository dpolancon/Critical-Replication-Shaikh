# Failed Process Map — From Iterative Passes to Editing System

## What the pass sequence achieved

The previous pass sequence succeeded at reducing overclaiming, separating statistical retention from economic admissibility, aligning the conclusion with the evidence, preserving the S0/S1/S2 architecture, making the chapter internally consistent, and reaching compile-ready status.

## What it failed to achieve

The process did not sufficiently transform the manuscript’s reader-facing genre. The result is safer than the 2.0 version but not strongly different in register, pacing, or critical-replication identity.

The problem is not mainly factual inconsistency. It is that the manuscript still reads in places like a cleaned editing artifact.

## Why the process failed

The old workflow was a linear correction chain:

`claim lock → econometric coherence → intro rebuild → results alignment → front-end naturalization → conclusion calibration → consistency audit`

Each pass optimized a local layer. The layers were not recombined inside bounded section-level loops before rewriting.

This made it possible to pass consistency audits while still failing genre fit.

## What must change

The next system must work through self-contained, bounded section experiments. Each experiment must state what failed, which layer owns the failure, which paragraphs are eligible, which contracts govern the change, what benchmark proves improvement, and what would count as a failed experiment.
